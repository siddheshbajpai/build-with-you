Curriculum — Make your own OS

12 modules, unlocked as you go. Every module ends with a working artifact you can show off.

01 The Bare Metal World 4 lessons

Before an OS exists, there is only the CPU: registers, memory mapped IO, and a board that powers on straight into whatever bytes we flashed. In this module you meet the machine with nothing between you and it.

  • How a CPU boots: reset vector, BIOS, bootloader
  • Registers, flags, and the stack
  • Reading the Intel manual for the fun parts
  • Lab 1: flash and boot your first 512 bytes
02 Writing the Bootloader 6 lessons

The bootloader is the first program on the machine: it sets up the stack, loads the kernel into memory, switches the CPU into protected or long mode, and jumps to the kernel entry point. Small program, enormous consequences.

  • Writing 16-bit real mode assembly
  • BIOS interrupts: disk, video, keyboard
  • Protected mode, GDT, and segment setup
  • Lab 2: bootloader that loads a kernel and prints a character
03 Your First Kernel 5 lessons

Now you own the machine. We build a kernel entry point, a working driver/console, and the long jump to 64-bit mode so you can write the rest of the OS in comfortable C.

  • Kernel entry, 32 → 64 bit long mode
  • Compiling with the exact linker script you need
  • Memory-mapped VGA text output
  • Lab 3: a kernel that prints "Build with YOU" to the screen
04 Interrupts & Hardware 6 lessons

Hardware interrupts are how the outside world gets a word in. We set up the IDT, handle timer ticks, and drive the keyboard — the moment your OS starts feeling alive.

  • CPU interrupt handling, the IDT, and ISR stubs
  • Programmable Interval Timer, and why you want a tick
  • Scancodes to characters: a PS/2 keyboard driver
  • Lab 4: type on the host keyboard and see it appear in your OS
05 Memory & Paging 6 lessons

Physical memory is a raw, flat, terrifying canvas. We give the CPU a page table and turn that canvas into a protected, virtual address space.

  • Physical vs virtual addresses, and the cost of a lookup
  • CR3, page tables, TLB, and a page fault
  • Heap allocation: malloc from scratch
  • Lab 5: a heap allocator that survives a fragmentation test
06 Processes & Scheduling 5 lessons

Now the kernel can multitask: multiple programs, separate address spaces, and a scheduler deciding who gets the CPU next. This is where an OS stops being a demo and starts being an OS.

  • Task control blocks and context switching
  • Round-robin and priority scheduling
  • System calls: the user/kernel boundary
  • Lab 6: run three programs at once and watch them switch
07 Filesystem & Shell 5 lessons

Storage gives memory a past. We build a simple filesystem, mount it, and give the user a shell so the whole thing becomes usable by a human — not just you.

  • Reading and writing a RAM disk image
  • Inodes, directories and a FAT-style table
  • A command shell with pipes and redirection
  • Lab 7: a shell where you can ls, cat, and cd your own disk
08 Finishing Touches 4 lessons

Polish, portability and the bits that make a demo feel like a product: a text editor, drivers, and getting your OS onto a USB stick for real hardware.

  • Write a tiny editor inside your OS
  • Drivers, serial ports, and a basic driver model
  • Booting your OS on real hardware
  • Final project: ship your OS as a bootable USB image

What you need

  • A 64-bit PC (any OS)
  • Free: QEMU, a C compiler, nasm, make
  • Curiosity and patience

What you leave with

  • A bootable OS on a USB stick
  • Debugging instincts for low-level bugs
  • A portfolio project nobody can buy

07 — faq

Questions, answered

What exactly is free?

Phase 1 of every course is free, forever — the full beginner phase, with every lesson, lab and starter project. No card, no sign-up, no countdown. The intermediate and advanced phases are part of Pro membership, because that is what keeps the creator building.

How does the $4.99 membership work?

Pro is a monthly membership that unlocks every phase of every course — including Make your own OS kernel engineering and full systems. It is a support-the-creator model: the money pays for the filming, the hardware, the lab time and the updates. Cancel whenever you like, in one click.

Do I need to know how to code?

Not for most paths. Make your own OS starts from zero: it teaches assembly from the first line. If you know Python or JavaScript already, you'll move faster but you can skip straight to the labs.

What do I need for the OS course?

A 64-bit machine and a handful of free tools (QEMU, GCC, NASM, make). We install everything together in Module 01 — Windows, Linux or macOS all work.

How long until I can boot my own OS?

Most people print to the screen in their first weekend (Module 03) and boot a real OS from a USB stick by week 6–8. Take your time; the labs are self-contained.

Do I get a certificate?

You get something better — a working project. Free members get a certificate for a completed Phase 1; Pro members get one for every phase they finish.
